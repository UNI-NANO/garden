# 칸 규칙 (`mods`) 형식

나무의 칸(`data/defs/trees/*.json`의 `nodes`)이 기술을 어떻게 바꾸는지 계산이 읽을 수 있게 적는 형식이다.
설명 글(`description`)은 사람이 읽는 것이고, `mods`는 같은 내용을 계산이 읽는 것이다. 둘은 늘 같은 말을 해야 한다.

- 형식의 정의: `src/schema/defs/tree.ts` (`ModSchema`)
- 찍은 칸 → 전투 기술: `src/rules/battle/build-skill.ts` (`buildSkill`)
- 전투에서 하는 일: `src/rules/battle/engine.ts` (`BattleSkill`의 선택 항목들)
- 테스트: `tests/battle-build-skill.test.ts` (도우미 `built(기본기, [칸…], {고른 쪽})`)

## 어떻게 적용되나

1. 기본기의 숫자(기술 기준표)에서 시작한다.
2. 그 기본기 아래에서 **찍은 칸**을 파일에 적힌 순서(뿌리에서 가까운 순서)대로 본다.
3. 칸의 `overrides`(역할·피해 종류·거리 바꿈)를 덮어쓰고, `mods`를 차례로 적용한다.
4. 고르는 보완 칸(`choice`)은 고른 쪽의 `mods`만 적용한다. `mods`가 없는 쪽은 아무 일도 하지 않는다.
5. 궁극기 칸은 건너뛴다. 궁극기는 따로 드는 기술이다(아래 「궁극기」).
6. 위력 = 기본 × (1 + 「위력 +」의 합) × 「위력 ×」의 곱. 기력과 쿨다운은 0 아래로 내려가지 않는다.

## 숫자 대신 말

기획서가 숫자 없이 말로만 적은 곳("조금 넓게", "크게")은 `amount`에 숫자 대신 **말**을 적는다.
말의 값은 `data/defs/battle.json`의 `words`에 하나씩 있다. 숫자를 고칠 때는 거기만 고친다.

| 말 | 지금 값 | 뜻 |
| --- | --- | --- |
| 판정 칸 조금 넓게 | 3 | 좋음 칸 폭 + |
| 판정 칸 넓게 | 6 | 좋음 칸 폭 + |
| 흐트러짐 + | 1.2 | 흐트러짐 피해 × |
| 흐트러짐 크게 | 1.5 | 흐트러짐 피해 × |
| 약하게 | 0.75 | 위력 × |
| 뒷줄 위력 | 0.85 | 뒷줄을 칠 때 위력 × |
| 적진 위력 | 0.2 | 적진에 남은 다음 턴 위력 + |
| 완벽 칸 조금 넓게 | 2 | 완벽 칸 폭 + |
| 방패 상대 위력 | 0.3 | 방패를 든 적에게 위력 + |
| 끈질김 턴당 | 0.1 | 끈질김: 턴마다 위력 + |
| 끈질김 최대 | 0.5 | 끈질김: 위력 +의 최대 |
| 끈질김 최대 + | 0.3 | 끈질김 최대를 올리는 값 |
| 칼등 위력 | 0.3 | 칼등: 피해 × (위력·흐트러짐은 그대로) |
| 집중 최대치 + | 2 | 집중 최대 중첩 + |
| 생포 보상 + | 0.5 | 생포 보상 배율 + (지금은 기록만) |
| 바늘 칸 | −12 | 단 한 번의 매듭: 좋음 칸 폭 + |
| 아주 큰 위력 | 1.5 | 산 가르기: 위력 × |
| 생포 체력 | 0.3 | 역날의 마음: 이 비율 이하로 남은 적을 생포 |

`words`에 없는 말을 쓰면 `npm run check:defs`가 막는다. 새 말이 필요하면 `words`에 먼저 넣는다(값은 사용자에게 확인).

## 조건 (`when`)

`"연계 중"` · `"연계 아님"` · `"대상이 흐트러짐"` · `"대상이 뒷줄"` · `"완벽"`(그 타를 완벽으로 쳤을 때)
· `"대상이 원거리"`(원거리 행동이 하나라도 있는 적) · `"대상에게 방패"`(적 카드 `traits`에 `방패`) · `"같은 대상"`(바로 앞 내 차례에 친 적).
조건이 붙은 규칙은 기술을 만들 때가 아니라 **칠 때** 따진다. 조건이 붙은 기력·쿨다운·타수는 쓰는 순간(연계를 잇기 전)의 상태로 정한다.
화면과 자동 전투는 `skillHitCount`·`skillEnergyCost`·`skillCooldown`·`skillGoodWidth`(`engine.ts`)로 이번에 쓸 때의 값을 읽는다.

## 타 (`hit`)

`"마지막"`: 마지막 타에만. `위력 +`·`위력 ×`·`좋음 칸`에 붙일 수 있다.

## 규칙의 종류

### 숫자
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `위력 +` | `amount`, `when?`, `hit?` | 위력 +비율 (0.1 = +10%). 여럿이면 더한다 |
| `위력 ×` | `amount`, `when?`, `hit?` | 위력 곱 |
| `흐트러짐 ×` | `amount`, `when?` | 흐트러짐 피해 곱 |
| `피해 ×` | `amount` | 피해에만 곱한다 (흐트러짐은 위력에서 계산되므로 그대로) |
| `좋음 칸` | `amount`, `when?`, `hit?` | 좋음 칸 폭 + (화면이 `skillGoodWidth`로 읽는다) |
| `완벽 칸` | `amount` | 완벽 칸 폭 + (좋음 칸보다 넓어지지 않는다) |
| `기력` | `add`, `when?` | 드는 기력 ± |
| `쿨다운` | `add`, `when?` | 쿨다운 ± |
| `타수` | `add`, `when?` | 타수 + (타 위력은 그대로) |
| `연계 보너스` | `amount` | 연계 보너스가 붙을 때 더 붙는 값 |
| `끈질김` | `perTurn`, `max` | 위력 + min(전투 턴 × perTurn, max) |
| `끈질김 최대` | `amount` | 끈질김의 max + |

### 맞히거나 쓰러뜨렸을 때
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `맞히면 기력` | `add`, `when?` | 한 타라도 맞으면 기력 ± (최대 기력을 넘지 않음) |
| `쓰러뜨리면 쿨다운` | `multiply` | 이 기술로 하나라도 쓰러뜨리면 걸린 쿨다운 × (내림) |
| `쓰러뜨리면 기력` | `add` | 이 기술로 하나라도 쓰러뜨리면 기력 + (한 번) |
| `생포` | – | 이 기술로 쓰러뜨린 적은 생포(`EnemyUnit.captured`, 사건 `생포`) |
| `생포 보상` | `amount` | 생포 기록의 보상 배율 + (지급은 전리품 정산 때) |
| `생포 체력` | `amount` | 친 뒤 체력이 최대 체력 × amount 이하인 맞은 적을 쓰러뜨려 생포 (`생포`도 켠다) |
| `흐트러뜨리기` | `when?` | 맞힌 타(가 조건에 맞으면) 대상을 바로 흐트러뜨린다 |
| `흐트러짐 절반` | – | 맞히면 대상의 남은 흐트러짐 게이지를 절반으로 |
| `방어 무시` | – | 대상의 방어를 0으로 본다 |
| `빗나가면 나에게 효과` | `effect` | 모든 타가 빗나가면 나에게 붙는다 |

### 효과
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `효과` | `effect`, `when?: "완벽"` | 붙이는 효과를 하나 더. `완벽`이면 완벽으로 친 타에만 더 붙는다 |
| `효과 교체` | `effects` | 기본기의 효과 칸을 통째로 바꾼다 |
| `효과 ×` | `effect`, `amount`, `when?` | 이 기술이 붙이는 그 효과의 양 × |
| `효과 유지` | `effect` | 이 기술로 붙인 그 효과는 붙은 턴의 턴 끝에 줄지 않는다 |
| `효과 상한` | `effect`, `add` | 이 기술로 붙일 때 최대 중첩 + (자세 기술이면 받아치기·자세 중에 붙는 것에도) |
| `터뜨리기` | `effect`, `when?: "완벽"` | 마지막 타에 그 효과를 모두 없애고, 없앤 만큼 방어를 무시하는 피해. `완벽`이면 마지막 타가 완벽일 때만 |
| `터뜨리기 모두` | – | 고른 적만이 아니라 맞은 적 모두의 효과를 터뜨린다 |
| `터뜨리기 강화` | `perStack` | 터뜨릴 때 중첩당 피해 +비율 |
| `터뜨리기 남김` | `share` | 터뜨린 뒤 그 비율만큼 남긴다 |
| `터뜨리기 흐트러짐` | – | 터뜨린 피해만큼 흐트러짐도 깎는다 |
| `터뜨리기 완벽` | `amount` | 마지막 타를 완벽으로 치면 터뜨리는 피해 × |
| `터뜨리기 빗나감` | – | 마지막 타가 빗나가면 그 효과가 모두 사라진다 |

효과 하나(`effect`)는 기술의 효과 칸과 같은 모양이다: `{ "id": "bleed", "amount": 1, "hits": [1, 2], "to": "대상" }`.

### 범위와 자리
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `나머지 대상` | `share` | 고른 적 말고 앞줄의 나머지에게도 그 비율의 위력 |
| `나머지 흐트러짐` | `share` | 나머지 대상이 받는 흐트러짐 비율 |
| `뒤 칸도` | – | 고른 적의 바로 뒤 칸도 맞는다 |
| `줄 전체` | `row` | 그 줄의 서 있는 적 전원을 친다. 앞줄이 서 있어도 그 줄을 고를 수 있다. 나머지가 같은 위력을 받게 하려면 `나머지 대상` 1을 함께 |
| `고를 수 있는 대상` | `when` | 조건이 맞는 적만 대상으로 고를 수 있다 (화면·자동 전투는 `skillTargets`로 읽는다) |
| `밀어내기` | – | 맞은 앞줄 적을 뒷줄로 밀고, 그 뒤에 있던 적을 앞으로 끌어낸다 |
| `밀려난 적 효과` / `끌려 나온 적 효과` | `effect` | 밀어내기에 딸린 효과 |
| `밀어내기 없음` | – | 앞 칸이 준 밀어내기(와 딸린 효과)를 없앤다 |
| `끌려 나온 적 치기` | `power?` | 끌려 나온 적도 밀어낸 적에게 들어간 위력으로 한 번 더 친다 (+power) |
| `뒷줄까지` | `amount` | 앞줄이 서 있어도 뒷줄을 고를 수 있다. 뒷줄을 치면 위력 × amount |
| `적진으로` | `amount` | 쓴 턴에는 모든 적이 나를 먼저 노리고, 다음 턴 주는 위력 + amount |

### 자세 (되받아치기)
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `자세` | `damageTaken?`, `parryWidth?`, `parryEnergy?`, `holdTurns?`, `counterHits?` | 자세 중 받는 피해 ×, 받아치기 칸 폭 +, 받아치면 기력 +, 자세가 이어지는 턴 +, 반격 타수 |
| `자세 찌르기` | `amount` | 자세를 잡으면서 고른 적을 기본 공격 위력 × amount로 찌른다 |
| `찌르기` | `power?`, `damageType?`, `stagger?` | 위 찌르기의 위력 +, 피해 종류, 흐트러짐 × |
| `찌르기 효과` | `effect` | 위 찌르기가 맞으면 붙는 효과 |
| `받아치면 효과` | `effect` | 받아치기에 성공하면 나에게 붙는 효과 |
| `자세 중 효과` | `effect` | 자세를 잡고 있는 턴의 끝마다 나에게 붙는 효과 |
| `대신 받기` | `damageTaken?` | 같은 줄 바로 옆 칸 동료를 노린 공격을 내가 대신 받는다(받아치기 판정도 나). 그 피해 × |

적 카드의 `traits`(`src/schema/defs/battle.ts`): 지금은 `방패`뿐. 나중에 지키기·방패 파괴도 이 표시를 쓴다.

## 궁극기

- 궁극기 칸에는 `skill`(단계 `궁극기`)과 `mods`를 적는다. 숫자는 기준표가 계산한다(위력 24 · 쿨다운 5 · 기력 5에 성격·타수·범위 보정).
- `buildUltimate`(`build-skill.ts`)가 궁극기 칸과 그 앞의 칸을 기본기까지 모두 찍었는지 확인하고 기술을 만든다.
- 루트의 갈래·보완 칸은 이어받지 않는다. 궁극기 칸의 `skill`과 `mods`만 쓴다. 피해 종류는 그 루트의 것을 `skill`에 적는다.
- 연계 역할은 모두 `끝내는`.
- 전투에는 `AllySetup.ultimate`로 하나를 든다. 전투 안에서는 다른 기술처럼 쿨다운·기력으로 쓴다(첫 턴부터).
- 「전체」 범위는 기준값대로 고른 적 말고는 위력 절반(`battle.json`의 `range.othersShare`)을 받는다.

## 예

```json
{
  "id": "sword.gale.a",
  "kind": "갈림길",
  "name": "넓게",
  "prev": "sword.gale.s2",
  "description": "나머지 대상도 80%.",
  "axis": "넓게 / 깊게",
  "overrides": { "role": "여는" },
  "mods": [{ "kind": "나머지 대상", "share": 0.8 }]
}
```

```json
{ "kind": "좋음 칸", "amount": "판정 칸 넓게", "when": "대상이 흐트러짐" }
```

## 칸을 채우는 순서

1. 기획서의 그 칸 설명을 읽고, 위 표의 규칙으로 적을 수 있는지 본다.
2. 적을 수 있으면 `mods`를 채우고, 나무의 `version`을 올린다.
3. 적을 수 없으면 **새 규칙 종류**가 필요하다: `ModSchema`에 추가 → `buildSkill`에서 `BattleSkill`의 선택 항목으로 옮김 → `engine.ts`에서 그 항목을 읽음 → 테스트. 뜻이나 숫자가 문서에 없으면 짐작하지 말고 사용자에게 묻는다.
4. `tests/battle-build-skill.test.ts`에 그 칸이 전투에서 하는 일을 테스트로 적는다.
5. `npm run check`, `npm run balance`.

## 아직 없는 것 (궁극기 ③-2에서 필요)

검술은 궁극기 9개까지 계산된다. 아래 8개는 기술 항목(`skill`)이 아직 없어 `buildUltimate`가 오류를 낸다.

| 궁극기 | 필요한 것 |
| --- | --- |
| 핏빛 실타래 | 「이번 전투에서 연계를 이은 횟수」처럼 전투 내내 세는 값 |
| 천번베기 | 판정 바 속도(화면이 읽을 값), 마지막 세 타 |
| 멎지 않는 바람 | 여러 턴 이어지는 기술(매 턴 시작에 저절로 치기) |
| 풀베기 | 쓰러뜨리면 한 번 더 (최대 횟수) |
| 기사의 맹세 | 아군 전체를 대신 받기, 성공한 수만큼 아군 전체에 효과 |
| 틈을 여는 검 | 적의 저항을 몇 턴 동안 0으로 |
| 흔들리지 않는 자 | 효과를 모두 써서 다음 몇 번의 공격에 걸리는 상태 |
| 진형 붕괴 | 앞줄 셋을 모두 뒷줄과 자리 바꾸기 |

그 밖에
- 생포 보상 지급(전리품 정산), 숨은 칸을 여는 조건, 지키기(성벽 부수기의 「지키기 무시」는 지키기가 생길 때)
- 자동 전투는 기력을 기본값(`skill.energy`)으로 보고 고른다. 조건으로 기력이 줄어드는 경우는 쓸 수 있어도 고르지 않을 수 있다

숫자가 문서에 없는 말은 `words`에 넣을 값을 사용자에게 확인받는다.
