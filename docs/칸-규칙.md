# 칸 규칙 (`mods`) 형식

나무의 칸(`data/defs/trees/*.json`의 `nodes`)이 기술을 어떻게 바꾸는지 계산이 읽을 수 있게 적는 형식이다.
설명 글(`description`)은 사람이 읽는 것이고, `mods`는 같은 내용을 계산이 읽는 것이다. 둘은 늘 같은 말을 해야 한다.

- 형식의 정의: `src/schema/defs/tree.ts` (`ModSchema`)
- 찍은 칸 → 전투 기술: `src/rules/battle/build-skill.ts` (`buildSkill`)
- 전투에서 하는 일: `src/rules/battle/engine.ts` (`BattleSkill`의 선택 항목들)
- 테스트: `tests/battle-build-skill.test.ts` (도우미 `built(기본기, [칸…], {고른 쪽})`)

## 어떻게 적용되나

1. 기본기의 숫자(기술 기준표)에서 시작한다.
2. 그 기본기 아래에서 **찍은 칸**을 파일에 적힌 순서(뿌리에서 가까운 순서)대로 본다.
3. 칸의 `overrides`(역할·피해 종류·거리 바꿈)를 덮어쓰고, `mods`를 차례로 적용한다.
4. 고르는 보완 칸(`choice`)은 고른 쪽의 `mods`만 적용한다. `mods`가 없는 쪽은 아무 일도 하지 않는다.
5. 궁극기 칸은 건너뛴다(따로 드는 기술이다. 아직 만들지 않았다).
6. 위력 = 기본 × (1 + 「위력 +」의 합) × 「위력 ×」의 곱. 기력과 쿨다운은 0 아래로 내려가지 않는다.

## 숫자 대신 말

기획서가 숫자 없이 말로만 적은 곳("조금 넓게", "크게")은 `amount`에 숫자 대신 **말**을 적는다.
말의 값은 `data/defs/battle.json`의 `words`에 하나씩 있다. 숫자를 고칠 때는 거기만 고친다.

| 말 | 지금 값 | 뜻 |
| --- | --- | --- |
| 판정 칸 조금 넓게 | 3 | 좋음 칸 폭 + |
| 판정 칸 넓게 | 6 | 좋음 칸 폭 + |
| 흐트러짐 + | 1.2 | 흐트러짐 피해 × |
| 흐트러짐 크게 | 1.5 | 흐트러짐 피해 × |
| 약하게 | 0.75 | 위력 × |
| 뒷줄 위력 | 0.85 | 뒷줄을 칠 때 위력 × |
| 적진 위력 | 0.2 | 적진에 남은 다음 턴 위력 + |

`words`에 없는 말을 쓰면 `npm run check:defs`가 막는다. 새 말이 필요하면 `words`에 먼저 넣는다(값은 사용자에게 확인).

## 조건 (`when`)

`"연계 중"` · `"연계 아님"` · `"대상이 흐트러짐"` · `"대상이 뒷줄"` · `"완벽"`(그 타를 완벽으로 쳤을 때).
조건이 붙은 규칙은 기술을 만들 때가 아니라 **칠 때** 따진다.

## 규칙의 종류

### 숫자
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `위력 +` | `amount`, `when?` | 위력 +비율 (0.1 = +10%). 여럿이면 더한다 |
| `위력 ×` | `amount`, `when?` | 위력 곱 |
| `흐트러짐 ×` | `amount`, `when?` | 흐트러짐 피해 곱 |
| `좋음 칸` | `amount`, `when?` | 좋음 칸 폭 + (화면이 `skillGoodWidth`로 읽는다) |
| `기력` | `add` | 드는 기력 ± |
| `쿨다운` | `add` | 쿨다운 ± |

### 효과
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `효과` | `effect`, `when?: "완벽"` | 붙이는 효과를 하나 더. `완벽`이면 완벽으로 친 타에만 더 붙는다 |
| `효과 교체` | `effects` | 기본기의 효과 칸을 통째로 바꾼다 |
| `효과 유지` | `effect` | 이 기술로 붙인 그 효과는 붙은 턴의 턴 끝에 줄지 않는다 |
| `효과 상한` | `effect`, `add` | 이 기술로 붙일 때 최대 중첩 + |
| `터뜨리기` | `effect` | 마지막 타에 그 효과를 모두 없애고, 없앤 만큼 방어를 무시하는 피해 |
| `터뜨리기 강화` | `perStack` | 터뜨릴 때 중첩당 피해 +비율 |
| `터뜨리기 남김` | `share` | 터뜨린 뒤 그 비율만큼 남긴다 |
| `터뜨리기 흐트러짐` | – | 터뜨린 피해만큼 흐트러짐도 깎는다 |

효과 하나(`effect`)는 기술의 효과 칸과 같은 모양이다: `{ "id": "bleed", "amount": 1, "hits": [1, 2], "to": "대상" }`.

### 범위와 자리
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `나머지 대상` | `share` | 고른 적 말고 앞줄의 나머지에게도 그 비율의 위력 |
| `나머지 흐트러짐` | `share` | 나머지 대상이 받는 흐트러짐 비율 |
| `뒤 칸도` | – | 고른 적의 바로 뒤 칸도 맞는다 |
| `밀어내기` | – | 맞은 앞줄 적을 뒷줄로 밀고, 그 뒤에 있던 적을 앞으로 끌어낸다 |
| `밀려난 적 효과` / `끌려 나온 적 효과` | `effect` | 밀어내기에 딸린 효과 |
| `뒷줄까지` | `amount` | 앞줄이 서 있어도 뒷줄을 고를 수 있다. 뒷줄을 치면 위력 × amount |
| `적진으로` | `amount` | 쓴 턴에는 모든 적이 나를 먼저 노리고, 다음 턴 주는 위력 + amount |

### 자세 (되받아치기)
| kind | 항목 | 하는 일 |
| --- | --- | --- |
| `자세` | `damageTaken?`, `parryWidth?`, `parryEnergy?`, `holdTurns?`, `counterHits?` | 자세 중 받는 피해 ×, 받아치기 칸 폭 +, 받아치면 기력 +, 자세가 이어지는 턴 +, 반격 타수 |
| `자세 찌르기` | `amount` | 자세를 잡으면서 고른 적을 기본 공격 위력 × amount로 찌른다 |
| `찌르기` | `power?`, `damageType?`, `stagger?` | 위 찌르기의 위력 +, 피해 종류, 흐트러짐 × |

## 예

```json
{
  "id": "sword.gale.a",
  "kind": "갈림길",
  "name": "넓게",
  "prev": "sword.gale.s2",
  "description": "나머지 대상도 80%.",
  "axis": "넓게 / 깊게",
  "overrides": { "role": "여는" },
  "mods": [{ "kind": "나머지 대상", "share": 0.8 }]
}
```

```json
{ "kind": "좋음 칸", "amount": "판정 칸 넓게", "when": "대상이 흐트러짐" }
```

## 칸을 채우는 순서

1. 기획서의 그 칸 설명을 읽고, 위 표의 규칙으로 적을 수 있는지 본다.
2. 적을 수 있으면 `mods`를 채우고, 나무의 `version`을 올린다.
3. 적을 수 없으면 **새 규칙 종류**가 필요하다: `ModSchema`에 추가 → `buildSkill`에서 `BattleSkill`의 선택 항목으로 옮김 → `engine.ts`에서 그 항목을 읽음 → 테스트. 뜻이나 숫자가 문서에 없으면 짐작하지 말고 사용자에게 묻는다.
4. `tests/battle-build-skill.test.ts`에 그 칸이 전투에서 하는 일을 테스트로 적는다.
5. `npm run check`, `npm run balance`.

## 아직 없는 것 (다음 단위에서 필요)

지금 `mods`가 채워진 것은 검술의 **보완 칸·갈림길과 그 보완 칸 32개**다. 끝갈래와 그 보완 칸, 숨은 칼등 갈래(38칸), 궁극기(17칸)는 설명 글만 있다. 이 칸들에는 지금 형식으로 적을 수 없는 것이 있다.

끝갈래·보완 칸
- **조건이 붙은 기력·쿨다운**: "혼자 쓸 때 쿨다운 −1", "같은 적을 연속으로 치면 기력 −1" (`기력`·`쿨다운`에는 아직 `when`이 없다)
- **쓰러뜨렸을 때**: "하나라도 쓰러뜨리면 쿨다운 절반", "쓰러뜨리면 기력 +1"
- **타수 바꿈**: "연계 없이 쓰면 4타"
- **효과의 양에 곱**: "연계 중이면 출혈 2배", "완벽이면 2배, 빗나가면 출혈 사라짐"
- **특정 타만**: "마지막 타 판정 칸 더 넓게", "두 번째 타 위력 +10%", 완벽 칸 폭
- **전투 길이**: "전투가 길수록 위력 증가"와 그 최대치
- **적의 종류를 보는 조건**: "원거리 적이면 2배", "방패를 든 적에게 위력 +" (적 카드에 표시가 필요)
- **자세 쪽**: 성공하면 집중, 옆 칸 동료 대신 받아치기, 자세 중 자신감, 찌른 적에게 취약, 효과 지속 +1턴, 연계 보너스 +10%
- **생포**(칼등): 피해 감소·흐트러짐 2배는 지금 규칙으로 되지만, 생포와 그 보상은 전리품 정산이 생긴 뒤

궁극기
- 궁극기를 **따로 드는 기술**로 만드는 길(지금 `buildSkill`은 건너뛴다)
- 여러 턴 이어지는 것(3턴 동안 매 턴…), 적 전체·줄 전체 대상, 쓰러뜨리면 다시 침, 판정 바 속도·바늘만 한 칸, 저항 0, 자신감을 써서 판정 칸 최대

숫자가 문서에 없는 말("크게 감소", "아주 큰 위력", "증가 최대치 +" 등)은 `words`에 넣을 값을 사용자에게 확인받는다.
